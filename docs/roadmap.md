# 路线图

> 每个阶段对应 TaskMaster 里的一个主任务（编号见括号），子任务和实时进度以 `task-master list` 为准。本文只记录阶段目标和验收标准。

## 里程碑一：AI 能通过内置组网操作远程设备的命令行

完成后，Linux 服务器上的 AI Agent 可以通过 MCP 操作 Windows 的命令和文件，不需要另装 Tailscale，不需要共享密钥，中文输出不乱码。

| 阶段 | 任务 | 验收标准 |
|---|---|---|
| 项目骨架与开发环境 | 1 | Go 模块、目录结构、测试、交叉编译 Windows/Linux/macOS 均通过，CI 可运行 |
| 连接层接口与 Tailscale 实现 | 2 | 新设备运行后打印登录链接，登录后加入内网，重启后不需要重新登录；可配置 Headscale 地址 |
| 设备发现与设备列表 | 3 | 按连接方式分组，列出同账号的所有节点，标出哪些运行 DeskBridge，显示在线状态、直连还是中继 |
| 节点协议与身份认证 | 4 | 能力报告、工具调用、超时、取消、结构化错误可用；非同账号请求被拒绝 |
| 命令与文件工具 | 5 | `sys.info`、`fs.*`、`proc.*` 在 Windows 和 Linux 上通过；中文 Windows 的命令输出和报错都是正确的 UTF-8 |
| 命令行客户端 | 6 | `deskbridge devices`、`deskbridge exec <设备> <命令>` 等可用，支持 `--json` 输出 |
| MCP 服务器 | 7 | Claude Code 通过 `deskbridge mcp` 列出设备并调用工具 |

## 里程碑二：人能看到并操作（基础版客户端）

完成后，用户在 Windows 上打开客户端，能看到所有设备，看到 AI 在每台设备上做了什么（正在运行的命令能看到实时输出），也能自己执行命令、浏览文件、取消 AI 的命令。2026-10-15 用户决定把这一阶段提前到桌面工具之前：AI 通过 DeskBridge 开发和使用时，用户需要看得到、插得上手。

| 阶段 | 任务 | 验收标准 |
|---|---|---|
| Windows 用户模式部署与自启 | 8 | 用户登录后节点自动在桌面会话中启动，崩溃后自动重启；`deskbridge install` / `uninstall` 可用 |
| 基础操作记录 | 11 | 每次工具调用写入本地 SQLite，区分 AI 和人，可以用命令行查询；同账号设备之间可以查询对方的记录；正在运行的调用能推送开始、输出片段和结束事件，任何同账号设备都能按 `request_id` 取消 |
| 基础版客户端 | 12（12.1–12.5） | Windows 上能运行；设备列表（连接方式、状态、延迟）、终端、文件浏览；操作记录页合并显示各设备的记录，能看实时输出并取消；截图和远程桌面只留入口 |

这一阶段用压缩包加 `deskbridge install` 安装，正式安装包和自动更新在任务 14。

## 里程碑三：AI 能操作 Windows 桌面

| 阶段 | 任务 | 验收标准 |
|---|---|---|
| 虚拟桌面技术验证 | 29 | 选定虚拟桌面的实现方式（先验证 Win32 隐藏桌面）：不报毒，常用程序能显示、截图、操作（ADR-0011） |
| 桌面控制权仲裁 | 23 | 按 ADR-0005：本地输入立即抢占 AI，租约、排队、提示和紧急停止；区分真实桌面和虚拟桌面 |
| Windows 桌面工具：截图、输入、窗口 | 9 | AI 能截图、点击、输入文字（含中文）、按快捷键、列出和切换窗口；支持多显示器和高分屏缩放；真实桌面和虚拟桌面都可用 |
| Windows 界面元素工具 | 10 | AI 能读取窗口的界面元素树，按名称查找并点击按钮、填写输入框；真实桌面和虚拟桌面都可用 |
| 客户端接入截图和桌面控制权 | 12（12.7） | 设备页能截图；设备行和设备页显示“AI 正在操作桌面”，可以接管、停止；操作记录详情能看 AI 截过的图 |

## 里程碑四：远程桌面和初版发布

范围见 [ADR-0009](decisions/adr-0009-first-release-scope.md)：只考虑自己的设备和局域网中配对的设备，远程桌面也在初版。

| 阶段 | 任务 | 验收标准 |
|---|---|---|
| 局域网发现与配对 | 28 | 同一局域网中的 DeskBridge 设备自动出现；输入 6 位配对码后可以使用全部工具；传输加密并校验设备公钥。完成后客户端默认显示局域网设备，可添加 Tailscale 后按连接方式切换（登录入口在标签状态区） |
| 远程桌面 | 15 | 局域网直连实时画面和输入；其他路径截图模式；每台设备一个独立窗口（ADR-0006）；可切换真实桌面和虚拟桌面（ADR-0011） |
| AI 画面查看 | 30 | 发起端能实时查看并回看 AI 拿到的截图和操作；被控端能通过查看窗口观看和接管虚拟桌面（ADR-0011） |
| 一站式自建中继 | 13 | **暂时搁置**（2026-10-07 用户决定，见 ADR-0006）。恢复时优先用 Tailscale peer relay |
| 打包与发布 | 14 | Windows 安装包、Linux 安装包、自动更新；发布流程自动化 |

| 阶段 | 任务 | 说明 |
|---|---|---|
| Windows 服务模式 | 16 | 系统服务 + 会话辅助进程，支持锁屏、UAC、开机未登录 |

## 顺序说明

- 里程碑一先做命令和文件，是为了先把组网、身份、协议和 MCP 这条链路打通。工具本身不复杂，但链路是所有后续功能的基础。
- 里程碑二把操作记录和客户端的基础部分提前（2026-10-15 用户决定）：AI 已经在用 DeskBridge 操作用户的设备，用户需要先能看到 AI 做了什么、自己也能操作。基础版客户端只用里程碑一已有的能力，截图和远程桌面等桌面工具完成后再接入，所以任务 12 拆成两部分：12.1–12.5 在里程碑二，12.7 在里程碑三。
- 里程碑二的第一个任务是自动启动（任务 8），完成后 Windows 重启也不需要人工恢复连接，客户端也总能连上本机节点。
- 桌面工具是项目的核心价值，紧接着在里程碑三完成。
- 操作记录的数据结构在任务 4 中就预留，任务 11 才做存储、查询和实时事件。
- 里程碑一完成后，开发本项目就从原型 AgentDesk 切换到 DeskBridge 自己（见 `docs/development.md` 的“远程执行通道”）。
- 虚拟桌面的实现方式影响控制权仲裁和所有桌面工具，所以技术验证（任务 29）排在任务 23、9 之前（ADR-0011）。
- 初版的完成标志是里程碑四的打包与发布（任务 14）。

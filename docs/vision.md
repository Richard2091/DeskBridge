# 项目定位

## 一句话

让 AI Agent 和人都能顺畅地操作多平台、多设备的命令行和图形桌面。

## 核心目标（必须做好）

1. **AI 操作 Windows 像 SSH 操作 Linux 一样顺畅。** 包括 SSH 做不到的部分：用户正在使用的图形桌面。
2. **人也能用同一套能力。** 人可以在客户端里执行命令、看截图、操作设备，不需要另装远程工具。
3. **多设备统一管理。** 看到并操作自己的所有设备（同一 Tailscale 账号的设备和局域网中配对的设备），包括用手机操作（规划中，见“支持平台”）。
4. **个人用户免费。** 内置组网，设备间直接通信；自建中继暂时搁置，见 ADR-0006。
5. **使用被控端自己的 AI 能力（规划中）。** 调用被控设备上的 Agent（如 Claude Code）、Skill 和本机 MCP 服务器，让多台设备上的 AI 能互相协作。见 [架构](architecture.md)。

## 加分项（核心之后再做）

初版只做操作记录和远程桌面，其余推迟，见 [ADR-0009](decisions/adr-0009-first-release-scope.md)。

- 操作记录：谁（AI 或人）在哪台设备做了什么，便于溯源和检查 AI 的行为。
- 权限控制：被控端按发起者授权（鼠标、键盘、命令、文件范围、删除等），危险操作在发起端确认（ADR-0008）。
- 外部设备：别人共享给你的设备，单独授权。
- 远程桌面：局域网直连用实时视频流 + 鼠标键盘；其他路径降级为截图模式。初版就做（ADR-0009）。

## 和现有工具的区别

| 工具 | 主要用户 | 缺少什么 |
|---|---|---|
| SSH | 人和 AI | 碰不到桌面；Windows 上编码和命令差异多 |
| RustDesk / ToDesk | 人 | 没有给 AI 的结构化接口；ToDesk 部分功能收费 |
| MeshCentral 等 RMM | IT 管理员 | 界面和接口为人设计，AI 很难使用 |
| Computer Use、UFO、Windows MCP 服务器 | AI | 大多假设 AI 和桌面在同一台机器，不负责跨网络、多设备 |

DeskBridge 的位置：**跨网络、多设备、AI 和人共用的那一层。**

## 支持平台

| 平台 | 命令和文件 | 桌面工具（AI） | 客户端界面 | 状态 |
|---|---|---|---|---|
| Windows 10/11 | 是 | 是 | 是 | 第一优先 |
| Linux 服务器（无桌面） | 是 | 不需要 | 不需要，由其他设备管理 | 第一优先 |
| Linux 桌面 | 是 | X11 先做，Wayland 后做 | 是 | 暂时搁置 |
| macOS | 预留 | 预留 | 预留 | 有设备后再适配 |
| Android | 待调研 | 被控：屏幕采集和触控操作，可行性待调研 | 是（控制电脑和其他手机） | 规划中，在 Windows 客户端之后 |

手机端分两部分：

- **控制端：** 用手机查看和操作电脑，以及其他手机。用和桌面客户端同一套 Flutter 代码（[ADR-0002](decisions/adr-0002-ui-framework.md)）。
- **被控端：** 让电脑或手机控制安卓手机。参考 RustDesk 的做法，用系统的屏幕录制接口采集画面，用无障碍服务注入触控。每次开始控制时可能需要手机上有人点“允许”，无人值守能做到什么程度待验证。iOS 系统不允许第三方应用注入输入，不做 iOS 被控端。

## 非目标

- 不做通用 VPN 或组网产品，组网能力只为设备互通服务。
- 不和 SSH 比拼终端体验；交互式终端（vim 等）不是早期目标。
- 不追求远程桌面的极致流畅，那是 RustDesk 和 ToDesk 的强项。
- 不面向企业的大规模设备管理（几百台以上）。

## 目标用户

个人开发者和小团队：让 AI Agent（比如运行在 Linux 服务器上的 Claude Code）操作自己家里或办公室的电脑，同时自己也能随时查看和接手。

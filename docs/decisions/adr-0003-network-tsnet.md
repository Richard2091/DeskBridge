# ADR-0003：组网内置 Tailscale（tsnet），可切换到自建 Headscale

- 状态：已提议，待用户确认
- 日期：2026-10-06

## 背景

原型最初用 SSH 反向隧道，不稳定；后来改为在两台设备上分别安装 Tailscale，已验证可用（Linux 服务器 ↔ Windows，经香港中继，约 230ms）。目标是让用户不用单独装组网软件，登录账号后就能看到并连接自己的设备，个人使用免费。

## 决定

1. **默认：** 程序内置 `tsnet`，使用 Tailscale 官方控制服务器。用户通过 OAuth（Google、GitHub、Microsoft 等）登录。
2. **可替换：** 控制服务器地址可配置为自建的 **Headscale**（BSD-3 开源）。
3. **中继：** 直连失败时走公共 DERP 中继；提供一键自建 DERP（和可选的 Headscale）的部署方案，见路线图。
4. **身份：** 用 `tsnet` 的 `WhoIs` 识别请求来源的账号和设备，取代原型的共享密钥。
5. **WireGuard 直连：** 作为后续的第二种传输方式，自带配对和密钥。

## 已知限制

- **“永久免费”取决于 Tailscale 的政策。** 据第三方报道，2026 年 4 月起个人版免费支持 6 个用户、设备数量不限（以 Tailscale 官网为准）。条款可能再变，Headscale 是保底方案。
- **对称 NAT 下直连困难。** 已实测：Windows 在运营商 NAT（对称型）后面，打洞失败，只能走中继。命令和截图不受影响，远程画面会卡顿，自建中继可以改善。
- **和已安装的 Tailscale 客户端共存：** 内置节点是独立节点，同一设备会出现两个条目。（待验证）
- **出口网络限制：** 某些网络对 Tailscale 控制服务器或 UDP 有限制，需要用自建方案。（待验证）

## 未采用的方案

- **SSH 反向隧道：** 不稳定，原型中已放弃。
- **Cloudflare Tunnel：** 面向 HTTP 服务发布，原始 TCP 需要额外的本地代理，不适合设备间互访。
- **只依赖系统已安装的 Tailscale：** 用户需要额外安装和配置，体验差。作为兼容模式保留：检测到系统 Tailscale 时也可以使用它。

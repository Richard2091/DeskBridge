# ADR-0010：连接方式各自独立，不跨连接方式合并设备

- 状态：**已接受（2026-10-08）**。用户在原型审查中提出
- 日期：2026-10-08
- 取代：[ADR-0007](adr-0007-pluggable-connection-layer.md) 第 4 条中“经多种连接方式可达时合并成一条”、第 6 条“选路”；[ADR-0009](adr-0009-first-release-scope.md) 第 2 条中“同一台设备只显示一次，放在 Tailscale 标签”

## 背景

ADR-0007、ADR-0009 规定：同一台设备经多种连接方式都可达时，按 DeskBridge 设备 ID 合并成一条，放在 Tailscale 标签，并自动选最快的路径。原型审查（2026-10-08）发现这条规则和“按连接方式切换”的界面互相矛盾：

- win-pc 和本机在同一局域网，但合并后只在 Tailscale 页出现。Tailscale 断开时，它被标成“无法连接”，提示文字却说“局域网设备不受影响”。
- 移除 Tailscale 后，这些设备不会回到局域网页。

用户的意见：连接方式（渠道）可以添加和删除；删除一种连接方式，它的页面和设备列表一起消失；局域网页始终保留局域网里的设备。从局域网页连接，走纯局域网方式；从 Tailscale 页连接，走 Tailscale 方式。

## 决定

1. **每种连接方式各自列出设备，不跨连接方式合并。** 同一台设备可以同时出现在 Tailscale 页和局域网页，各是一条。
2. **从哪个页面连接，就走哪种连接方式。** 不在连接方式之间自动选路或切换。Tailscale 内部的路径（局域网直连、跨网直连、中继）仍由 Tailscale 决定，功能分层（ADR-0006）按这条路径判断。
3. **每种连接方式按自己的信任规则。** 局域网页的设备要先配对，Tailscale 页的设备按同一账号信任。同一台设备在 Tailscale 里可用，不代表在局域网页里免配对。
4. **连接方式之间互不影响。** Tailscale 断开、退出或移除，只影响 Tailscale 页；局域网发现关闭，只影响局域网页。
5. **DeskBridge 设备 ID 继续使用：**
   - 用于身份校验和局域网配对（保存对方的设备公钥）。
   - 在同一种连接方式内部去重（例如设备上同时装了 Tailscale 客户端、在内网中出现两个节点）。
   - 用于标识设备本身的状态：桌面控制权、正在运行的命令、操作记录按设备 ID 记录，与经哪种方式连上无关。
6. **界面：** 设备页地址带连接方式，`#/devices/<连接方式>/<设备>/<标签>`；设备页头部显示“连接方式 · 路径 · 延迟”。远程窗口按“设备 + 连接方式”区分，同一台设备经两种方式各开一个窗口是允许的。从操作记录打开设备时，优先当前连接方式，其次局域网，再次 Tailscale；都不可用时提示原因。

## 影响

- ADR-0007 第 4、6 条按本决定修改，第 1–3、5、7 条不变。
- ADR-0009 第 2 条的“只显示一次”被取代，其余不变。
- `docs/architecture.md` 的“连接层与身份”、`docs/ui-design.md` 第 2.2 节和第 7 节同步修改。
- 任务 3（设备列表）：不再做跨连接方式合并；任务 28（局域网发现与配对）不受影响。

## 风险

- 同一台设备出现两次，用户可能不清楚该点哪一条。界面在设备行和设备页显示连接方式和路径来区分；实际使用后再看是否需要提示“这台设备也在局域网中”。
- 用户可能从较慢的连接方式打开设备（例如 Tailscale 经中继，而局域网可以直连）。初版不自动切换，靠路径和延迟提示；是否提示“局域网里有更快的连接”，实际使用后再定。

## 未采用的方案

- **保留合并，Tailscale 不可用时自动改走局域网：** 用户选择连接方式各自独立，行为更直接，也和“按连接方式切换”的界面一致。

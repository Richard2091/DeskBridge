# ADR-0004：开源，只参考其他项目的设计，不复制代码

- 状态：已决定（2026-10-06）。用户在了解 AGPL 不禁止他人公开源码商用后，确认选择 AGPL-3.0
- 日期：2026-10-06

## 决定

1. **DeskBridge 开源。**
2. **参考其他开源项目的设计思路，不复制它们的源代码。** 特别是 RustDesk（AGPL-3.0）：复制其代码会要求整个项目使用 AGPL。
3. **可以作为依赖库使用宽松许可证（MIT、BSD、Apache-2.0）的库，** 例如 `tsnet`、`pion/webrtc`、`modernc.org/sqlite`。依赖的许可证清单见 [references.md](../references.md)。
4. **许可证：AGPL-3.0。** 目标是作者保留做商业版的权利，同时防止别人拿去做闭源的商业产品。

## AGPL-3.0 能做到和做不到的

- **能做到：** 任何人修改、分发 DeskBridge，或者把它作为网络服务提供给别人使用，都必须以 AGPL 公开完整源代码。别人无法做闭源的商业版。
- **做不到：** AGPL 不禁止别人商用。别人可以拿 DeskBridge 收费（例如收费托管、收费支持），只要他们公开源代码。如果要完全禁止别人商用，只能用“源码可见”类许可证（如 BSL、PolyForm Noncommercial），但那样就不再算开源（不符合 OSI 定义）。
- **作者做商业版：** 作者对自己写的代码不受许可证限制，可以另外以商业许可证出售（双许可证，RustDesk 等项目采用类似模式）。
- **外部贡献：** 如果接受别人的代码贡献，需要贡献者签署贡献者协议（CLA），授权作者以商业许可证使用他们的代码。否则商业版里不能包含这些代码。

## 对依赖的影响

AGPL 项目可以使用 MIT、BSD、Apache-2.0 的依赖。规则不变：不复制 RustDesk 等项目的代码，只参考设计。

## 执行规则

- 写代码时可以阅读参考项目的文档和代码来理解设计，但实现必须自己写。
- 新增依赖前检查许可证；只用 MIT、BSD、Apache-2.0 等宽松许可证的依赖。虽然 AGPL 项目可以使用 GPL 依赖，但那样作者就无法再提供闭源的商业版。
- 在 `references.md` 中记录参考了哪个项目的哪部分设计。

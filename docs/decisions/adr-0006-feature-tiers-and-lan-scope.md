# ADR-0006：功能分层，实时远程桌面先只支持局域网，中继搁置

- 状态：**已接受（2026-10-07）**。用户决定先搁置中继，和 macOS 一样保留以后实现的余地
- 日期：2026-10-07
- 补充（2026-10-08）：实时画面仍只在局域网直连开放；初版远程桌面在其他路径降级为截图模式，复用工具层的截图和输入能力（ADR-0009）。这不再把非局域网路径的远程桌面入口完全关闭。

## 背景

任务 24.3 实测（见 [spikes/results.md](../../spikes/results.md) 的“画面传输：网络场景”）：

- 局域网直连：60 fps 8 Mbps 实际 56 fps，送达 p50 约 16 ms，完全够用。
- 跨境经公共中继：只有约 0.4 Mbps，而且波动很大，不能看画面。
- 两台测试电脑都在难以打洞的 NAT 后面，没有 IPv6，路由器和光猫不能改，跨网络只能靠中继。
- 自建中继（Tailscale peer relay、DERP、RustDesk 的 hbbr）都需要一台带宽充足的服务器，还要处理授权规则、端口、服务器出口带宽，工作量和不确定性都不小。

工具类功能（命令、文件、截图、点击、界面元素）每次只传几 KB 到几百 KB，经公共中继也能用（任务 21 已验证经香港中继约 0.5 秒）。

## 决定

1. **功能按网络条件分层：**

   | 层 | 功能 | 网络要求 |
   |---|---|---|
   | 工具层 | 命令、文件、进程、截图、鼠标键盘、窗口、界面元素、MCP、操作记录 | 任何能连上 Tailscale 内网的路径，包括公共中继。不做额外开发 |
   | 画面层 | 实时远程桌面画面（实时视频流 + 输入） | **暂时只支持局域网直连**。其他路径下降级为截图模式，复用工具层的截图和输入能力 |

2. **中继功能搁置**（任务 13）。不开发自建中继，不测试经中继看画面。公共中继只作为 Tailscale 自带的后备，承载工具层。
3. **保留以后实现中继的余地：**
   - 节点之间一律用 Tailscale 内网地址通信，不直接用局域网 IP，以后路径变成中继时上层代码不用改。
   - 设备列表记录每台设备的路径类型（局域网直连、跨网直连、中继及中继位置）和延迟（任务 3）。
   - 画面层是否开放由一个函数判断，输入是路径类型和实测带宽、往返时间；现在的规则是“只有局域网直连才开放”，以后放开中继时只改规则。
   - 画面流从一开始就做码率自适应、只保留最新帧和截图降级。即使在局域网，Wi-Fi 丢包也需要这些（1% 丢包会让 4 Mbps 的帧率减半）。
   - 控制服务器地址保持可配置（可换 Headscale，见 ADR-0003）。

## 恢复中继时的方向

记录下来供以后参考，现在不做：

- 优先用 Tailscale peer relay（客户端 1.86 及以上）：在一台网络条件好的服务器上运行 `tailscale set --relay-server-port=<端口>`，在策略文件的 grants 中授予 `tailscale.com/cap/relay`，并放行对应的 UDP 端口。不需要域名和证书。2026-10-07 已在一台中国的云服务器上部署过中继端口，但授权规则没加，没有实测。
- 自建 DERP 作为后备，用于只允许 HTTPS 的网络。
- 中继服务器要离两端都近，出口带宽要实测；中国的家庭宽带跨境上行很差，两端在中国时中继也应在中国。

## 影响

- 任务 13 改为搁置。
- 任务 24.3 不再补测中继路径；手机作为发送端的测试并入任务 26。
- 任务 24.5 的 RustDesk 对照只在局域网做，不自建 hbbs/hbbr。
- 任务 15 只做局域网实时画面，按本 ADR 预留开放判断和截图降级。
- 里程碑一不受影响：Linux 服务器经公共中继调用 Windows 的工具属于工具层。

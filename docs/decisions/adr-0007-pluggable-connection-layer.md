# ADR-0007：连接层可替换，Tailscale 是第一种实现

- 状态：**已接受（2026-10-07）**。用户提出：以后可能支持多种连接方式，不应和 Tailscale 强绑定
- 日期：2026-10-07
- 补充（2026-10-08）：第 7 条的分组方式改为按连接方式分组，初版增加局域网发现与配对，见 [ADR-0009](adr-0009-first-release-scope.md)
- 补充（2026-10-08）：第 4 条中“跨连接方式合并成一条”和第 6 条“选路”被 [ADR-0010](adr-0010-independent-connection-channels.md) 取代：连接方式各自独立，从哪个页面连接就走哪种方式；设备 ID 仍用于身份、配对和同一连接方式内部去重

## 背景

[ADR-0003](adr-0003-network-tsnet.md) 选定内置 Tailscale（`tsnet`）。按原来的写法，设备列表从 `tsnet` 的本地状态读取，身份用 `tsnet` 的 `WhoIs` 识别，界面上的分组也叫“Tailscale 设备”。如果上层代码直接调用 `tsnet`，以后增加 WireGuard 直连（任务 19）或其他方式时，节点协议、设备列表、身份、权限和界面都要跟着改。

任务 2（组网）、3（设备列表）、4（节点协议与身份）都还没有开始，现在调整成本最低。

## 决定

1. **分层：** 节点协议、设备列表、权限、MCP 和界面只依赖“连接层”接口，不直接调用 `tsnet`。Tailscale 是连接层的一种实现，不是产品的核心概念。

2. **连接层接口（草案，任务 2 和 4 中细化）：**

   | 能力 | 内容 |
   |---|---|
   | 启动与登录 | 启动、登录（返回登录链接或需要的参数）、退出；状态：已连接、需要登录、断开及原因 |
   | 对端列表 | 每个对端：连接方式内的 ID、名称、地址、是否在线、路径类型（局域网直连、跨网直连、中继及位置）、延迟 |
   | 建立连接 | 拨号到对端的某个端口；在本机监听端口 |
   | 身份 | 根据连接查出对方是谁，返回统一的身份结构：主人（账号或配对关系）、设备、来自哪种连接方式 |
   | 事件 | 对端上线下线、路径变化、断线和重连 |

3. **实现：**
   - **Tailscale（第一种）：** 内置 `tsnet`。改用自建 Headscale 只是控制服务器地址不同；“使用系统已安装的 Tailscale”（ADR-0003 的兼容模式）是同一实现的另一种模式。
   - **WireGuard 直连（第二种，任务 19）：** 不需要账号，两台设备配对后直接连接。
   - 其他方式按需要再评估。

4. **DeskBridge 自己的设备 ID（跨连接方式合并的部分已被 ADR-0010 取代）：** 每台设备生成一个 DeskBridge 设备 ID（密钥对，私钥放在系统密钥库），在能力报告中返回。同一台设备经多种连接方式都能连通时，按设备 ID 合并成一条。设备上同时装了 Tailscale 客户端、在内网中出现两个节点的问题，也用它合并。是否还要在连接层之上做一次双向认证，在任务 4 中确定（待验证）。

5. **“我的设备”由连接方式判断：** Tailscale 是同一账号的节点；WireGuard 是配对过的设备。别人的设备都按 [ADR-0008](adr-0008-permissions-and-initiator-confirmation.md) 只给明确授予的权限。

6. **选路（已被 ADR-0010 取代）：** 同一台设备有多条路径时选最快的：局域网直连 > 跨网直连 > 中继。功能分层（ADR-0006）按实际使用的路径判断。

7. **界面和文案不绑定 Tailscale：**
   - 设备分组叫“我的设备”“外部设备”，不叫“Tailscale 设备”。
   - 设备信息显示“连接方式 · 路径 · 延迟”，例如“Tailscale · 局域网直连 · 4 毫秒”。
   - 设置中的这一页叫“连接方式”，按连接方式分组显示状态、账号和选项。
   - 首次登录先选择连接方式，再登录。

## 影响

- ADR-0003 仍然有效，范围收窄为“连接层的第一种实现”。
- 任务 2：实现连接层接口和 Tailscale 实现。任务 3：设备列表来自连接层，按设备 ID 合并。任务 4：身份使用连接层返回的统一结构。任务 19：作为连接层的第二种实现。
- 节点之间仍然只用连接层给出的地址通信，不直接用局域网 IP（ADR-0006 第 3 条不变）。

## 未采用的方案

- **上层直接调用 `tsnet`：** 现在省一点事，以后每增加一种连接方式都要改上层多处。
- **一开始就实现多种连接方式：** 没有需求驱动。先只做 Tailscale，接口按 Tailscale 和 WireGuard 两种情况设计，避免只适合一种。

# ADR-0002：桌面客户端选用 Wails + 网页前端

- 状态：已提议，待用户确认
- 日期：2026-10-06

## 背景

需要一个跨平台的桌面客户端：登录、设备列表、执行命令、看截图、看操作记录，后期显示远程画面。希望只维护一套界面代码，并且和 Go 核心直接集成。

## 候选

| | Wails | Tauri | Electron | Fyne（纯 Go 界面） |
|---|---|---|---|---|
| 后端语言 | Go，同一进程 | Rust（Go 只能作为外部子进程） | Node.js（Go 作为子进程） | Go |
| 界面技术 | 网页（TS/React） | 网页 | 网页 | 自绘控件 |
| 安装包体积 | 小（用系统 WebView） | 小 | 大（自带 Chromium） | 小 |
| 界面能力 | 好，可复用为网页控制台 | 好 | 好 | 一般，复杂界面较难 |

## 决定

使用 **Wails**，前端用 **TypeScript + React**。

- 和 Go 核心在同一个进程，没有额外的通信层。
- 同一份前端代码可以由节点直接作为网页控制台提供，无界面的 Linux 服务器也能从其他设备管理。
- Windows 使用系统自带的 WebView2，Linux 使用 WebKitGTK。

## 风险

- Wails v3 尚在开发，先用稳定的 v2；之后评估升级。（待验证：开始开发时确认当时的稳定版本。）
- Linux 版依赖 WebKitGTK，需要在安装说明中列出。
- 客户端界面是可选的：核心功能（节点、命令行、MCP）不依赖 Wails，无界面环境只构建命令行版本。
